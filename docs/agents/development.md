# 작업 시작과 스킬 연결

이 프로젝트는 GitHub `minjunkim-labs/mobile-runtime`의 기존 Issue·라벨·도메인 설정을 유지한다. 작업 전 [이슈 추적](issue-tracker.md)·[라벨](triage-labels.md)·[도메인 읽기](domain.md)를 확인한다. 관련 용어집·ADR과 티켓의 확정 완료 조건을 읽는다. 없는 도메인 문서는 필요가 생길 때 만든다.

프로필은 `AGENTS.md`의 `프로필: 1인`이다. 트렁크·되돌리기 판정·병합·`main` 경계는 repo-baseline `POLICY.md`를 따른다. 적용한 커밋은 [저장소 설정](../REPOSITORY_SETUP.md)에 있다. 제품 검증과 이 저장소의 CI는 이 문서와 [리뷰 절차](review.md)를 따른다.

## 설정 확인

스킬 원문은 저장소의 `.claude/skills/`에 있다. 이 문서는 거기 있는 스킬만 가리킨다. 설치 manifest를 따로 찾거나 스킬을 설치·활성화하지 않는다.
기존 tracker·라벨 매핑·도메인 문서·AGENTS 연결이 유효하면 재설정하지 않는다. 누락·변경이 있으면 이 문서와 [이슈 추적](issue-tracker.md)·[라벨](triage-labels.md)·[도메인 읽기](domain.md)를 직접 고치거나 소유자에게 묻는다. 이 프로젝트의 canonical 지침은 root `AGENTS.md`다. `CLAUDE.md`(`@AGENTS.md` 한 줄) 말고 도구별 중복 지침·shim·symlink를 만들지 않는다. 자동 로딩을 확인할 수 없는 도구는 작업 시작 때 AGENTS와 위 문서를 명시적으로 읽는다.

## 작업 크기에 맞는 진입

- 작은 수정·명확한 버그: 요청 또는 기존 티켓의 기대 동작·완료 조건·검증을 확인하고 바로 구현한다. 필요하면 `tdd`나 `diagnosing-bugs`를 쓴다. 별도 명세·티켓 분해를 강제하지 않는다.
- 여러 작업으로 나뉘는 확정 기능: `to-spec`·`to-tickets`는 사람만 부르는 스킬이라 에이전트가 직접 실행하지 않고 이름을 대어 실행을 권한다. 사용자가 실행하면 `to-spec`로 명세와 검증 경계를 확인하고, `to-tickets`로 검증 가능한 작은 수직 작업과 실제 차단 관계를 작성한다. 사용자와 티켓 크기·의존성을 확정한 뒤 기존 tracker에 발행한다. 기존 명세·티켓은 재사용한다.
- 미확정 결정: 필요한 `grilling`·`research`·`prototype`으로 근거와 결정을 확인한 뒤 위 경로로 들어간다. 무엇을 만들고 무엇이라 부를지 정할 일이 크면 `grill-with-docs`·`wayfinder`(사람만 부르는 스킬)의 이름을 대고 실행을 권한다. 제품 결정권과 기존 Issue 운영 규칙은 유지한다.

## 준비된 작업과 통합

실제 후보 게이트·기기 검증을 시작할 때는 [검증 준비와 수집](validation.md)을 먼저 확인한다.

1. tracker의 실제 선행 티켓·현재 담당자·착수 기록을 확인한다. 선행 작업이 모두 완료된 티켓만 선택한다. `ready-for-agent` 라벨만으로 차단 관계를 무시하지 않는다.
2. 명세 전체는 하나의 통합 브랜치에서 완성한다. 여러 맥락이 필요한 기능에서만 이렇게 하며, 오래 유지하는 별도 dev 브랜치로 만들지 않는다. 병렬 구현은 티켓별 브랜치·worktree·파일 소유권을 분리하고 시작 기준과 보고 전 통합 tip을 맞춘다. 런타임에 하위 에이전트가 없으면 같은 의존성 순서로 직렬 실행하고 차이를 기록한다.
3. 각 작업을 관련 검사 후 통합하고 새로 준비된 티켓을 선택한다. 넓은 기계적 변경은 expand → migrate → contract로 나눈다. 중간 검증이 불가능하면 최종 통합·검증 티켓을 명시한다.
4. 최종 전체 diff에서 명세 완료 조건·회귀·작업 간 연결을 검사한다. [자체 리뷰](review.md)대로 별도 컨텍스트에서 `REVIEW.md` 리뷰(민감한 파일을 건드리면 보안 리뷰 포함)와 직접 수정·재검증을 완료한다.
5. 필수 CI 성공 뒤 병합은 `AGENTS.md`의 병합 줄을 따른다. 통합 브랜치 검증과 main 반영을 구분한다. tracker의 완료 관례로 티켓을 닫고, 부모 명세는 전체 완료 조건을 확인한 뒤 승인된 범위에서만 종료한다. 작업용 worktree를 정리한다.
